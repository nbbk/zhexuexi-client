## 0. 结论先行

1. **能做。** 全新自研客户端 + 现成的 sing-box 核心，是市面主流客户端都在走的路（Hiddify、NekoBox 都是这个结构），不是从零发明。
2. **第一版只原生接自己的两仓，不接 Xboard / V2board。** 落地 `landing-node`（Xray / sing-box 双核心）+ 中转面板 `relay-node`（1.3.29）是第一版的唯一原生后端。Xboard / V2board 各做一个适配器，排第二阶段，绝不三套面板并行开工。
3. **技术选型结论：Flutter + sing-box 核心。** 一套 Dart 代码出 Windows 和 Android 两个端；sing-box 一个核心覆盖 VLESS / Trojan / VMess / SS2022 / Hysteria2 / TUIC，刚好对上落地节点的全部协议。不要自写代理协议栈，不要用 mihomo 再套一层——落地是 sing-box / Xray 双核心，客户端核心选 sing-box 兼容面最广。
4. **远程换域名、换订阅，不用重装——靠远程配置中心，而且优先走你自己的面板 / Worker，不另起一套不相干的服务。** 客户端内置一个可替换的配置中心地址列表，启动时拉取签过名的配置 JSON（订阅地址、面板域名、公告、最低版本、强制更新标志）；换域名、换订阅只改配置中心的内容，用户下次启动 / 下次订阅更新就生效。配置中心本身被封，有备用地址链 + 本地缓存的最后一份好配置兜底（见 §6）。
5. **品牌全部可替换。** 应用名、Logo、主色、订阅地址、面板域名、客服 / 公告链接做成一张变量表（见附录 A）：改远程配置里的项，重启客户端即生效，不用重新打包；改包内图标 / 包名 / 签名，才需要重新打包。
6. **工期（助手全程开发、用户只负责真机验证的前提下）：约 9–13 周。** 阶段 0 方案与钉死接口 1 周 → 阶段 1 MVP 4–6 周 → 阶段 2 Xboard / V2board 适配 2–3 周 → 阶段 3 打磨与发布 2–3 周。工期是范围，不是死日期；每阶段验收不过就顺延，不赶工期硬上。
7. **流量限制用户 2026-11-21 23:27 拍板选方案 2（节点侧按人计量）：所有节点都要能限流，中转和直连都要数到。** 中转仍走面板 1.3.25 的 A 方案（中转机上按人计数）；直连走节点侧按人计量（落地 agent + 每人一个 UUID + Xray stats 上报回面板，见节点侧按人计量完整方案 v1 `node-side-metering-plan.md`），客户端只展示不自算。代价写在 §1.4：每人一个 UUID，现有订阅链接全部变掉、客户端须重新导入一次；停用要删用户 + 重启 Xray，闪断约 1–2 秒；sing-box 落地先只数总量。节点侧计量排在客户端 MVP 之前 / 并行做，不然后面直连流量照样随便跑。

## 1. 与现有两仓的原生适配（优先级最高，先写这一节）

> 原则：客户端第一版是“你家两仓的官方客户端”，不是“又一个通用订阅导入器”。通用订阅导入（粘贴任意订阅链接）可以作为兜底入口保留，但主路径必须是：打开就认得你的面板、你的节点、你的分组和限流。

### 1.1 两仓分工（一句话）

| 仓库 | 角色 | 客户端要认的东西 |
|---|---|---|
| `landing-node` | 落地节点：真正出流量的服务器 | Xray / sing-box 两种核心、6 种协议、TLS / 明文两套端口（见 §1.2） |
| `relay-node`（面板 1.3.29） | 中转 + 管理面板：转发、中转、订阅、用户、分组、限流、备份 | 订阅（三种格式自适应）、`subscription-userinfo` 头、按人令牌、分组、按人限流、集中管理、备份整机迁移（见 §1.3） |

中转本身（realm）客户端不用管：中转只转发字节流，客户端看到的节点地址就是中转地址或落地直连地址，协议和 TLS 端到端直通，客户端不需要知道中间有没有中转。

### 1.2 落地节点 `landing-node`：协议与端口映射（客户端直接解析，不要只当通用订阅处理）

落地两种核心，一台机器只装一种，客户端按订阅内容自动识别，不用用户选核心。

**Xray 核心（`tiktok-xray` 容器）**

| 模式 | 协议 | 端口 | 客户端处理 |
|---|---|---|---|
| TLS | VLESS + WS + TLS | 443（Caddy 终止 TLS，反代 Xray） | sing-box 出站 `vless`，`transport: ws`，`tls.enabled: true`，SNI = 节点域名 |
| 明文 | VLESS + WS（明文） | 8080 | `tls.enabled: false`，地址填 IP，端口 8080；界面上标“明文·仅测试”，不建议长期用 |

**sing-box 核心（`singbox-node` 容器）**

| 模式 | 协议 | 端口 | 客户端处理 |
|---|---|---|---|
| TLS | VLESS / Trojan / VMess，走 WS 经 Caddy | 443 | 同上，三种协议分别生成 sing-box 出站 |
| TLS | Shadowsocks 2022 | 8388（TCP + UDP，直连） | `shadowsocks` 出站，`method: 2022-blake3-aes-128-gcm`（以订阅实际字段为准） |
| TLS | Hysteria2 | 8443 / UDP | `hysteria2` 出站，UDP 必须走 TUN 或系统代理的 UDP 路径，不能只开 HTTP 代理 |
| TLS | TUIC | 8444 / UDP | `tuic` 出站，同上，UDP 路径必填 |
| 明文 | VLESS / Trojan / VMess | 8080 / 8081 / 8082 | 明文 WS，分别映射；SS2022 仍是 8388 |

**原生适配的具体要求（写进 MVP 验收）：**

1. 订阅拉下来后，客户端不直接把 Clash YAML / sing-box JSON 丢给核心，而是先解析成自己的节点模型（`Node{协议、地址、端口、UUID/密码、传输、TLS、SNI、WS 路径、名称、分组、来源}`），再由节点模型生成 sing-box 配置。这样做的好处：测速、分组、按协议显示、按人限流提示都能按字段做，而不是按字符串猜。
2. 节点名保留 twin 后缀（`-中转` / `-直连`），分组显示时中转和直连分开展示，用户一眼分得清。
3. 明文节点在界面上必须有明确标识（灰色“明文”角标 + 设置页一句话说明“明文 WS 易被识别，仅临时测试，长期用 TLS”），不能和 TLS 节点混在一起让用户误选。
4. HY2 / TUIC 节点在仅开“系统代理”模式下要提示“UDP 协议需开 TUN 模式才完整可用”，不要静默降级成半残连接。
5. 追加节点、删除节点、换核心这些事仍在落地服务器上做（跑 `install.sh --add-node` / `--del-node`），客户端只负责拉新订阅，不在客户端里改落地配置。

### 1.3 中转面板 `relay-node` 1.3.29：客户端第一版原生对接清单

面板 1.3.29 是客户端的最低版本门：**低于 1.3.29 的面板，客户端要明确提示“请先把面板升到 1.3.29”，不要静默用旧口径跑。** 版本门写在远程配置里（`min_panel_version: "1.3.29"`），也写在客户端启动检查里。

| 面板能力（1.3.29 已有） | 客户端第一版怎么接 | 备注 |
|---|---|---|
| 订阅：Clash YAML / sing-box JSON / base64，按客户端 UA 自适应；也可 `?format=clash\|singbox\|base64` 显式指定 | 客户端固定带自己的 UA（例如 `Zhexuexi/1.0`，UA 里不带机场特征词），默认拿 sing-box JSON（`?format=singbox`），解析失败时回退 base64，再失败回退 Clash YAML；三种格式都要有解析器和回归测试 | 面板已验证：Clash YAML 含 dns 段、策略组、15 个检测域名；sing-box JSON 目前是 legacy DNS 格式，sing-box 1.14 移除前须迁移一次——客户端解析器要同时兼容 legacy 与新格式，见 §10 未核实项 |
| `subscription-userinfo` 响应头：upload / download / total / expire | 每次订阅更新后解析该头，首页显示“已用 / 总量 / 到期日”三格；没有该头时显示“—”，不编数据 | 面板 1.3.24 起 expire 带令牌到期；1.3.27 修过管理面板 userinfo 头缺失 |
| 按人订阅令牌：每人一条 `sub_` 令牌，只存 SHA-256 哈希，明文只显示一次 | 客户端登录 / 绑定时只存令牌本身（加密存储，见 §5.4），绝不把令牌打进日志、截图、崩溃上报；令牌失效（订阅返回 404）时首页提示“订阅已失效，请重新绑定”，不要反复重试刷面板 | 通用订阅令牌与按人令牌分开存，互不串 |
| 分组（1.3.26）：一组 = 一组落地 + 一组用户，成员归属以 SubUser / MergedSub 的 GroupID 为准 | 客户端节点列表按分组展示（组名就是面板里的组名）；改组后下次订阅更新即同步，客户端不缓存旧分组 | 通用订阅不进分组，客户端不给通用订阅画分组 |
| 按人限流（1.3.25，A 方案）：只给开了限流的用户建独立转发，80% 提醒 / 100% 停用，端口段默认 30000–39999，三种重置模式 | 客户端不自己算限流：限流由面板 + 中转侧执行。客户端只做两件事——① 把 userinfo 的用量如实展示；② 收到 100% 停用时显示面板给的状态，不要自己猜“是不是限流了” | **设计限制，必须写进界面文案**：直连流量不经过中转机，面板数不到，A 方案管不到直连。客户端不在直连节点上画“已用流量”，只在中转节点 / 总量上画，避免误导 |
| 集中管理：管理面板 + 被管面板，`rpt_` 令牌配对 | 第一版客户端只连“用户自己的那台面板”（订阅面板），不做多面板切换。集中管理是面板管理员的功能，放在第二阶段的“多面板”里，不要塞进 MVP | 客户端登录态与面板管理后台登录态分开：客户端用订阅令牌，不用面板管理员账号密码登录 |
| 备份整机迁移 `migration_enc`（1.3.29）：设了迁移口令的备份换新面板直接恢复，旧订阅链接继续可用；未设口令保持旧脱敏口径 | 对客户端的影响是正面的：面板换机器、换域名后，只要订阅令牌还在、订阅地址通过远程配置中心换了新地址，客户端不用重装、不用重新绑定。客户端要做的只是“订阅地址从远程配置中心取，不要写死”（见 §6），以及订阅 404 时按 §6 的备用地址链重试 | 客户端自己不存面板备份、不参与 `migration_enc` 解密；那是面板侧的事 |
| 订阅路径可自定义（现为 `/x9f2/`）、订阅对外域名可填 Worker 域名、通用文件名可自定义 | 客户端绝不硬编码 `/x9f2/`、绝不硬编码面板域名。订阅地址全量来自远程配置中心（见 §6），本地只存“上次成功的那份”做缓存 | 面板改了订阅路径后，旧路径链接会 404——客户端要在订阅更新失败时先拉远程配置，再报“订阅地址已变，正在用新地址重试”，而不是直接报“订阅失效” |

**待核实（执行前必须在 `relay-node-kit-160/panel/` 代码里确认，见 §10）：**

- 面板有没有给客户端用的“用户自查”接口（例如用订阅令牌查自己的流量 / 到期 / 分组），还是只能靠订阅 + userinfo 头？如果没有，MVP 就只用订阅 + userinfo 头，不要在方案里假装有。
- sing-box JSON 的新 DNS 格式字段名、Clash YAML 的 dns 段在客户端解析时要不要原样透传给核心，还是由客户端自己生成 DNS 配置（推荐后者，见 §5.3）。
- 集中管理下多面板的订阅合并格式（合并订阅），第一版不做，但适配层要预留 `source: 面板ID` 字段。

### 1.4 面板换域名后客户端如何不重装（与 §6 联动）

流程只有四步，缺一步都不行：

1. 面板换域名（或 Worker 换域名）→ 2. 你在远程配置中心改掉订阅地址和面板域名（改配置，不改客户端）→ 3. 客户端启动 / 定时拉取远程配置，发现订阅地址变了，用新地址重新拉订阅 → 4. 旧订阅令牌不变，节点照常连上，用户无感知。
2. 如果远程配置中心本身的域名也被封，客户端按备用地址链逐个试（见 §6.4），全部失败时用本地缓存的最后一份好配置 + 上次的订阅继续工作，并在首页顶部提示“配置中心暂时连不上，正在用上次的配置”，不要直接断连。
3. 强制更新（`force_update: true` + `min_app_version`）只用于“旧版客户端解析不了新订阅格式”这种真断裂场景，不要拿来当日常推送手段。

### 1.5 Xboard / V2board：第二阶段，各做一个适配器

- 两家面板的订阅地址形状就不一样：V2Board 是 `https://host/api/v1/client/subscribe?token=<token>`，Xboard 是 `https://host/<subscribe_path>/<token>`（默认路径 `s`）；用户自查接口也有差异（例如 `GET /api/v1/user/getSubscribe` 返回 `data.subscribe_url`、`GET /api/v1/user/info` 查余额 / 流量 / 到期）。来源：RocketProxy 的 V2Board / Xboard 面板说明（GitHub，2026 年核对），见 §2。
- 所以适配层设计成“一个面板一种适配器”，共用同一个节点模型和同一个界面（见 §5.2），不要写一套“通用面板适配”假装能通吃。
- 第二阶段才做，MVP 不做；第一版的适配层接口要预留 `PanelAdapter` 这个抽象，不要把 relay 面板的逻辑写死在界面层。

| Clash Verge Rev | Windows、macOS、Linux（桌面，无移动端） | mihomo（Clash.Meta） | 首页代理组 + 订阅 + 规则 + 连接 + 日志 + 设置 | 多订阅管理，自动更新；Merge（YAML 合并）与 Script（JS）增强配置 | 节点延迟测试；v2.5.8 起用真实 TLS 握手延迟 | 系统代理 + TUN 双模式；系统代理守护（异常退出后自动恢复）；GEOSITE / GEOIP 规则集 | Tauri + Rust，包小（<15MB 级）；配置能力最强，但只做桌面。来源：clashvergerev.com；clash-meta.org（v2.5.9，2026-09-26） |
| Shadowrocket / Streisand | iOS 为主（另有 Mac / Windows / Android 免费版，来源站点说法不一，以 App Store 为准） | 自研规则引擎 + 各协议核心 | 首页开关 + 服务器列表 + 配置（规则文件）+ 数据（流量 / 日志） | 订阅 URL / 剪贴板 / 二维码；多订阅共存；手动 / 定时更新 | 节点延迟测试；流量与速度分 Wi-Fi / 蜂窝 / 直连 / 代理统计 | 规则 / 全局 / 直连三档；分应用；DoH / DoT / DoQ；URL 重写 | iOS 上最成熟、最好用的标杆；付费（iPhone / iPad 约 $2.99 一次性）；不提供节点、无账号体系。来源：shadowrocket1.com；valebyte.com 的 VLESS Reality 指南 |

### 2.2 提炼：哲学系要抄的

1. **首页只有一个大开关 + 当前节点 + 实时速率。** 抄 Hiddify / Shadowrocket：打开就能连，不用先学概念。FlClash、Verge Rev 的“代理组”概念第一版不要暴露给用户。
2. **节点列表 = 名字 + 延迟 + 分组，一行一个，点一下就切换。** 抄 NekoBox 的分组测速 + Hiddify 的自动选最快；延迟用真实握手延迟，不要用 ICMP ping 冒充。
3. **订阅更新 = 一行状态 + 一个刷新按钮。** 抄 v2rayNG 的“订阅组”思路但界面要更简单：只显示“上次更新时间 + 剩余流量 + 到期日”，不要把订阅 URL、令牌明文摊在首页。
4. **模式只有三档：规则 / 全局 / 直连。** 抄 Shadowrocket 的三档命名，不要学 Verge Rev 的 Merge / Script——那是给极客的，第一版不做。
5. **设置页分两层：常用设置在上面，高级设置折叠在下面。** 抄 FlClash 的 Material You 分层：常用（开机自启、自动更新订阅、通知）一眼可见；高级（DNS、TUN、MTU、分应用）默认收起。

### 2.3 提炼：哲学系不要抄的

1. **不要抄 NekoBox 的“把 sing-box 全部选项摊出来”。** 规则集、插件、出站编辑器第一版一个都不要。用户要的是简单简洁好用，不是第二个 sing-box 文档。
2. **不要抄 Verge Rev 的 Merge / Script。** 用户自己就是运营者，规则由服务端（面板订阅）下发，客户端不要让用户写 JS 改配置。
3. **不要抄“多订阅、多面板、多账号并存”的复杂入口。** 第一版只认一个面板（自己的 relay 面板），一个订阅；多面板是第二阶段的事。
4. **不要抄免费 WARP / 试用节点那套。** Hiddify 内置免费配置是获客手段，你的客户端是自家节点的官方客户端，内置的就是你自己的节点，不要再塞第三方免费节点。
5. **不要在首页放连接日志、DNS 查询、请求列表。** 那是排障用的，放设置页的“诊断”里，平时不打扰用户。

## 3. 产品定位与功能清单

### 3.1 定位（一句话）

**哲学系 = 你家两仓的官方客户端：打开就能连，节点自动选最快的，流量和到期一眼看得见，换域名、换订阅不用重装。**

用户画像：你的现有用户（用小火箭 / FlClash / Hiddify 在连你的节点的人），以及以后新拉的用户。他们不懂协议、不想学规则，只想“点一下就能上 TikTok”。

### 3.2 功能清单（P0 / P1 / P2）

**P0——MVP 必做（没有就不能发布）**

| # | 功能 | 验收标准 |
|---|---|---|
| P0-1 | 内置订阅（零配置开箱） | 全新安装、联网后 10 秒内自动拉到节点列表，不用用户粘贴任何链接；订阅地址来自远程配置中心（见 §6），不是写死在代码里 |
| P0-2 | 一键开关 | 首页一个大开关：开 = 启动核心 + 接管流量；关 = 停核心 + 恢复系统代理 / 断开 VPN。开关状态、当前节点、实时上下行速率在一屏内看得见 |
| P0-3 | 节点列表 + 分组 | 按面板分组展示（中转 / 直连分组分开）；每行：节点名、延迟（ms）、状态（可用 / 超时 / 停用）；点一下切换节点，切换后 3 秒内生效 |
| P0-4 | 延迟测速 + 自动选节点 | 一键“全部测速”；自动选节点 = 测速后选延迟最低的可用节点，每 5 分钟后台重测一次（仅在已连接时）；测速失败的节点标灰，不自动选 |
| P0-5 | 剩余流量与到期显示 | 首页三格：已用 / 总量、剩余、到期日；数据来自 `subscription-userinfo` 头；没有该头时显示“—”，不编数据；到期前 7 天 / 3 天各提醒一次 |
| P0-6 | 订阅更新 | 手动刷新按钮 + 每天自动更新一次（仅 Wi-Fi 下自动更新，移动数据下不自动拉）；更新失败时显示原因（网络不通 / 订阅 404 / 令牌失效），不静默失败 |
| P0-7 | 公告 | 启动时拉远程配置里的公告；有新公告时首页顶部横条显示，点一下展开全文；公告可带一个链接（例如换域名通知） |
| P0-8 | 模式：规则 / 全局 / 直连 | 默认规则；三档切换立即生效；规则由订阅下发（TikTok / 社交 / 流媒体走代理，其余直连），客户端不让用户手写规则 |
| P0-9 | 系统代理 / TUN | Windows：系统代理默认开，TUN 可选开（须管理员权限，见 §4.4）；Android：VpnService 接管流量（首次弹系统 VPN 授权），TUN 默认开 |
| P0-10 | DNS 防泄漏 | 默认 DoH（1.1.1.1 / 8.8.8.8）+ DoT 兜底，只解析 IPv4，不回落明文 UDP 53；节点域名走代理解析；设置页可查看当前 DNS 配置，不可关闭防泄漏 |
| P0-11 | 品牌可替换（远程部分） | 应用名、Logo、主色、订阅地址、面板域名、公告链接全部走远程配置（见 §6 / 附录 A）；改远程配置后重启客户端即生效，不用重新打包 |

**P1——第二批（MVP 发布后 1–2 个版本内做）**

| # | 功能 | 验收标准 |
|---|---|---|
| P1-1 | Xboard / V2board 适配器 | 各做一个适配器（见 §1.5）；登录（邮箱 + 密码）→ 拉订阅 → 显示流量 / 到期；两家接口分开实现，共用节点模型和界面 |
| P1-2 | 多面板切换 | 面板列表（自己的 relay 面板 + Xboard + V2board），切换面板后节点列表、流量、到期跟着换；每个面板的令牌分开加密存 |
| P1-3 | 分应用代理（Android）/ 分进程（Windows） | Android：选哪些应用走代理、哪些直连；Windows：先做“浏览器走代理、其余直连”的预设，不做逐进程自选 |
| P1-4 | 流量统计（本机） | 今日 / 本月 / 累计上下行（客户端本地统计，仅供参考，口径写明“本机统计，与面板用量可能有 1–2 分钟延迟”）；不要和面板的按人限流用量混为一谈 |
| P1-5 | 订阅令牌轮换 / 重新绑定 | 令牌失效时一键重新绑定（扫码或粘贴新订阅）；旧令牌立即作废，不留残留 |
| P1-6 | 诊断页 | 一键导出诊断包（核心日志近 200 行 + 当前节点 + 延迟 + DNS 配置，不含令牌明文）；“测一下能不能上 TikTok”一键检测（沿用面板 15 个检测域名思路，客户端只测 3–5 个） |

**P2——以后再说（不排进前两个阶段）**

- 购买 / 续费 / 支付（走面板网页，不在客户端内做支付，避免应用商店支付抽成与审核）
- 邀请 / 推广返利
- 多语言（先只做简体中文）
- macOS / Linux / iOS（iOS 须苹果开发者账号 + App Store 审核，单独立项再议）
- 自定义规则编辑器、脚本、插件
- 桌面小组件 / 快捷指令 / 托盘菜单的高级玩法（托盘只保留“开关 + 退出”）

### 3.3 不做的事（本方案明确排除）

- 不在客户端里做面板管理后台（加落地、改限流、看所有用户）——那是 relay 面板网页的事。
- 不做节点买卖、不要在客户端里内置任何第三方免费节点。
- 不绕过应用商店支付、不做任何“骗验证、钻空子”的分发手段。
- 不收集用户浏览记录、不上传节点使用明细到任何第三方；崩溃上报默认关，用户手动开才开。

## 4. 技术选型（给结论 + 权衡）

### 4.1 结论

| 层 | 选型 | 版本锚点（2026-11-21 查到，执行时重核） |
|---|---|---|
| 界面 + 业务逻辑 | **Flutter（Dart）**，一套代码出 Windows + Android | 最新稳定版 3.50.1（Dart 3.14.0），2026-11-20 发布；来源：docs.shorebird.dev 的 Flutter 版本页。注意：3.50 把内置 material / cupertino 库拆成独立包，新项目默认用 `material_ui` / `cupertino_ui`，脚手架要按新版写 |
| 代理核心 | **sing-box**，通过 Flutter 插件接 `libbox` | sing-box 1.14.x（`sing_box` 插件称内置 1.14.4；`flutter_sing_box` 3.0.3 称内置 1.14.3，Android + Windows 双端）。来源：pub.dev 的 `sing_box` / `flutter_sing_box` / `sing_box_flutter` 包页。注意：sing-box 1.14 已移除 legacy DNS 格式，配置必须用新 DNS 格式——面板 sing-box JSON 目前是 legacy 格式，客户端要自己生成 DNS 配置，不要原样透传面板的 DNS 段 |
| 插件（待二选一，阶段 0 定） | `sing_box`（社区插件，Android VpnService + Windows，含 Clash API）或 `flutter_sing_box`（Android + Windows，含远程配置导入、Clash API、VPN 管理） | 两者都是社区插件，非 SagerNet 官方；执行前要对照各自最新 README 核对：是否支持 Windows TUN、是否支持 URLTest 自动选节点、是否支持 Clash API 查流量。不要凭本方案的版本号直接锁定 |
| 本地存储 | Flutter 侧：`flutter_secure_storage`（令牌、密钥）+ `shared_preferences` / SQLite（节点缓存、设置、流量统计） | 令牌绝不存明文文件；Android 用 Keystore、Windows 用 DPAPI（经插件实现） |
| 网络 | `dio`（HTTP，订阅拉取、远程配置拉取，带超时 + 重试） | 订阅拉取超时 15 秒，重试 2 次；远程配置拉取超时 10 秒 |
| 状态管理 | `riverpod` 或 `bloc` 二选一（阶段 0 定，选一个全项目统一） | 不要混用两种状态管理 |
| 打包分发 | Windows：MSIX / exe 安装包 + 绿色 zip 双份；Android：arm64-v8a APK 为主，另出 universal APK | 见 §4.4 |

### 4.2 为什么是 Flutter + sing-box（而不是别的）

- **一套代码两个端。** FlClash、Hiddify 已经证明这条路走得通：Flutter 界面 + 核心库，Windows 和 Android 界面基本一致，用户换设备不用重新学。
- **核心与落地同源。** 落地 sing-box 节点就是 sing-box 跑的，客户端核心也用 sing-box，协议、传输、TLS 行为一致，出问题时服务端和客户端用同一套概念排障。
- **协议全。** sing-box 一个核心覆盖落地全部 6 种协议，不用再套 Xray 核心做双核心切换（双核心 = 双倍测试量，第一版不要）。
- **不要选的路：** Tauri + mihomo（Clash Verge Rev 的路）只做桌面，没有 Android，得再写一套移动端；纯原生（Kotlin + C# 各写一套）工期翻倍；自写代理核心（哪怕只写 VLESS）是重复造轮子，且 TLS / 抗探测做不过 sing-box。

### 4.3 备选方案（如果 Flutter 插件踩坑）

- 备选 A：Flutter 界面 + Go 写一个常驻核心服务（sing-box 以库方式跑在 Go 服务里，Flutter 通过本地 Clash API / HTTP 与之通信）。优点是核心完全可控，缺点是多一个进程、安装包变大、Windows 服务安装更麻烦。
- 备选 B：Android 用 NekoBox 同款结构（原生 Android + libbox），Windows 用 Go + Fyne 写一个极简界面。优点是各端都原生，缺点是两套界面代码，维护成本翻倍。
- 决策点在阶段 0：先用 Flutter 插件跑通“启动核心 + 连一个 VLESS 节点 + 测速”最小验证，不过再切备选 A。不要在没验证的情况下直接写全量界面。

### 4.4 本机限制与打包现实（必须如实写，不许写成已能做到）

- **本机现在没有 Flutter、Dart、Java、Android SDK。** 2026-11-21 实测：`which flutter dart java` 无结果，只有 Go 1.22.2，磁盘剩余 146G（够装 SDK，但 SDK + 模拟器 + Flutter 全套约 10G+，须在阶段 0 安装验证）。
- **Flutter Windows 包在 Linux VM 上编不出来。** Flutter 官方规则：Windows 应用只能在 Windows 上编（Shorebird 文档亦明确“Desktop apps build on their own OS”）。所以 Windows 包必须在以下二者之一上编：① 用户的 Windows 真机（装 Flutter + Visual Studio 2022 C++）；② CI（GitHub Actions 的 `windows-latest` 跑 `flutter build windows`）。用户此前已定 GitHub 账号无 CI 额度、测试全本地——Windows 打包若走 CI，须用户另行拍板是否接受用 Actions 的免费额度；不接受就走用户 Windows 真机打包。
- **Android APK 可在本机尝试编。** 装 Android SDK + NDK + JDK 17/21 后，`flutter build apk --split-per-abi` 可出 arm64-v8a 包；但首次装 SDK、配签名、跑通真机安装，都要在阶段 1 实测，不要写“已验证”。
- **签名：** Windows：无代码签名证书时 SmartScreen 会弹“未知发布者”，用户点“仍要运行”才能装；有 EV / OV 证书可消警告，但须用户购买（约数百美元 / 年，价格以实际为准），第一版先不买，用“官网直发 + 绿色 zip”绕过安装器警告。Android：自签名 keystore 即可，密钥文件（`.jks` + 密码）由用户保管，丢了就不能再以同一签名升级，**必须备份**。
- **分发：** 第一版只走官网直发（下载页放 exe + APK），不走 Microsoft Store / Google Play。原因：Google Play 对代理类应用审核严，sing-box 官方亦在 1.12.0 发布说明里写过应用商店更新困难；Microsoft Store 审核同样不确定。官网直发 + 远程配置中心，才是换域名不用重装的前提。
- **权限：** Windows TUN / 系统代理须管理员权限：首次启动要弹 UAC，服务模式（常驻）须装一次系统服务；Android 须 VpnService 授权（首次弹系统 VPN 授权框）+ 前台服务 + 忽略电池优化（否则厂商后台杀进程会断连）。这些权限申请的文案要在界面上写清楚用途，不要只弹系统框让用户猜。

### 4.5 版本与依赖冻结规则

- 阶段 0 冻结：Flutter 版本、sing-box 插件版本、sing-box 核心版本、Dart SDK 版本，写进 `pubspec.lock`，全项目统一，不许各写各的。
- 核心升级（例如 sing-box 1.14 → 1.15）单独走一个小版本验证：先跑订阅解析回归 + 真机连通测试，通过才升。
- 面板版本门：客户端 `min_panel_version = 1.3.29`，面板低于此版本时启动检查提示升级，不静默降级。

```
│  / 远程配置缓存（最后一份好配置）/ 流量统计                 │
└─────────────────────────────────────────────────────────┘
        │                │                │
   远程配置中心     relay 面板订阅     Xboard/V2board
  （面板/Worker，   （Worker 域名，     （第二阶段，
   见 §6）           见 §1.3）          各一个适配器）
```

### 5.2 关键设计

- **节点模型统一。** 不管订阅是 sing-box JSON、Clash YAML 还是 base64，也不管面板是 relay、Xboard 还是 V2board，解析后都变成同一个 `Node` 模型，界面、测速、核心配置生成只认这个模型。面板差异只留在适配层。
- **面板适配层 `PanelAdapter`（接口先定，实现分阶段）：**
  - `RelayPanelAdapter`（第一版）：订阅拉取 + userinfo 解析 + 远程配置拉取（见 §6）。
  - `XboardAdapter`、`V2boardAdapter`（第二阶段）：登录 + `getSubscribe` + `user/info`（字段以实测为准，见 §10）。
  - 适配器只返回节点模型 + 账户模型（剩余流量、到期日、公告），不直接操作界面。
- **订阅解析：** 三种格式都要有解析器——sing-box JSON（`outbounds` 数组）、Clash YAML（`proxies` 数组 + `proxy-groups` 只取节点、不取规则，规则由客户端按面板下发的分流生成）、base64（逐行 `vless://` / `vmess://` / `trojan://` / `ss://` 链接）。解析失败的节点单独列“解析失败 N 个”，不丢整个订阅。
- **测速：** 用 sing-box 的 URLTest（对每个节点发一次真实 HTTPS 握手请求，取延迟），不要用 ICMP ping；测速地址用 `https://www.gstatic.com/generate_204`（与面板 Clash 订阅的 url-test 一致）；超时 3 秒算失败；自动选节点 = 延迟最低且可用。
- **规则 / 分流：** 默认规则模式：TikTok（`tiktok.com` 等后缀，沿用面板 1.3.23 的清单）+ 社交 + 流媒体走代理，其余直连；全局 = 全部走代理；直连 = 全部直连。规则由客户端内置（与面板订阅的规则清单对齐），不在界面上让用户编辑。
- **DNS 防泄漏：** sing-box DNS 配置由客户端自己生成：DoH `https://dns.cloudflare.com/dns-query` 与 `https://dns.google/dns-query` 双路，DoT 兜底；只解析 IPv4；节点域名走代理解析；不回落明文 UDP 53。面板订阅里的 DNS 段不原样透传（legacy 格式在 sing-box 1.14 已移除）。
- **流量统计口径：** 面板用量（userinfo 头）是权威口径，用于“剩余流量 / 到期”展示；客户端本机统计（Clash API 查核心流量）只用于首页实时速率和 P1 的今日 / 本月统计，口径要写明，两者数字对不上时以面板为准。

### 5.3 核心配置生成

- 客户端每次切换节点 / 改模式 / 更新订阅后，重新生成一份 sing-box 完整配置（JSON），校验通过后再热重载核心；校验失败时保留旧配置继续跑，并在界面提示“配置生成失败，已保持上次连接”。
- 配置模板由客户端内置，节点部分由节点模型填充；不要把面板下发的完整 Clash YAML / sing-box JSON 直接喂给核心（格式、DNS、规则都可能与客户端核心版本不匹配）。
- 连接日志、DNS 查询日志默认只保留最近 200 行，存在本机，不上传。

### 5.4 安全

- 订阅令牌、面板登录密码（第二阶段）只存安全存储（Android Keystore / Windows DPAPI），不存明文文件，不打日志，不进崩溃上报，不进诊断包。
- 远程配置 JSON 必须验签（见 §6.3），验签失败不应用。
- 客户端不收集浏览记录；遥测默认关。
- 备份整机迁移是面板侧的能力（`migration_enc`），客户端不参与解密、不存面板备份。

## 6. 远程替换订阅与域名（用户明确要求，单独写透）

> 目标：用户装好客户端后，你换域名、换订阅地址、换面板域名、改公告、改品牌色，都不用用户重新安装。改配置中心的内容就行。

### 6.1 方案选型：优先走自己的面板 / Worker，不另起服务

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A（首选） | **面板本身出配置**：relay 面板新增一个公开只读接口（例如 `GET /client-config.json`，无须登录，返回签过名的配置 JSON），Worker 加一条 `/config/` 路由反代到面板 | 配置和订阅同源，换域名时只改一处；面板换机器后备份整机迁移（`migration_enc`）把配置一起带过去 | 须给面板加一个小接口（阶段 1 的面板侧工作量，约半天–1 天，须用户拍板是否进面板版本）；面板挂了配置也拉不到（有缓存兜底，见 §6.4） | **首选** |
| B（并行首选） | **Worker 出配置**：在现有 Cloudflare Worker（已在反代订阅）里加一个路由，返回配置 JSON（内容存在 Worker KV 或直接写在 Worker 代码里） | 不用改面板代码；Worker 本身就是你换域名时的第一道门，改 Worker 配置即改客户端配置；Cloudflare 边缘节点抗封性比单台面板好 | Worker 代码要多维护一份配置；KV 内容改动要走 Worker 部署 | **与 A 并行：A 为主，B 为备用地址之一** |
| C（备用） | **GitHub Raw / R2 静态文件**：配置 JSON 放私有仓 Raw 或 R2 公开桶，客户端按地址列表逐个试 | 完全不依赖面板和 Worker，面板全挂也能拉到配置；改文件即生效 | Raw 有缓存延迟（约 45–90 秒）；公开桶地址本身也可能被封；须另管一份文件 | **只做备用地址，不做主地址** |
| D（不选） | 另起一套独立的配置中心服务（新域名、新服务器、新后台） | — | 多一套要维护的东西，域名又多一个被封面；与面板两套事实来源会打架 | 不做 |

**落地做法：主地址 = 方案 A（面板出配置，经 Worker 反代）；备用地址 = 方案 B（Worker 直出）+ 方案 C（GitHub Raw / R2）。客户端内置 3 个地址，按顺序试，第一个成功且验签通过的就用。**

字段说明：

| 字段 | 含义 | 改了之后 |
|---|---|---|
| `config_version` | 配置版本号，单调递增 | 客户端只接受比本地缓存新的版本，不回退 |
| `min_app_version` / `force_update` | 最低可用客户端版本 / 是否强制更新 | 低于最低版本时首页弹升级提示；`force_update` 为真时弹全屏升级，不让继续用旧版连 |

| `signature` | Ed25519 签名（见 §6.3） | 验签失败的配置一律不用 |

### 6.3 签名 / 校验防篡改

1. **签名算法：Ed25519。** 私钥只存在你手里（离线保管，不进仓库、不进面板、不进 Worker 代码）；公钥编译进客户端（写死在代码里，换公钥才需要重新打包——公钥几乎不换）。
2. **签什么：** 对除 `signature` 字段外的全部内容做规范 JSON（按 key 排序、无空格）后签名；客户端收到后先验签，验签通过才解析应用，验签失败直接丢弃、用本地缓存的最后一份好配置，并记一条本地日志（不上传）。
3. **传输层也要 HTTPS：** 配置中心地址一律 HTTPS；HTTP 地址客户端直接拒绝，不拉。
4. **不要把订阅令牌放进配置 JSON。** 配置里只有订阅地址模板 / 面板域名这类公开信息；每个用户的订阅令牌是用户绑定时才有的，存在用户本机安全存储里。配置被别人拿到，也拿不到任何一个用户的订阅。

### 6.4 拉取、失败回退与配置中心本身被封

```
启动 → 按地址列表顺序拉远程配置（超时 10 秒/个）
  → 第一个验签通过的 → 应用 → 缓存到本地（最后一份好配置）
  → 全部失败 → 用本地缓存的最后一份好配置 → 首页提示“配置中心暂时连不上，正在用上次的配置”
  → 本地也没有缓存（全新安装且首次拉取就失败）→ 用包内内置默认值（订阅地址为空，首页提示“首次启动需要联网拉取配置”，并给一个“重试”按钮 + 一个手动粘贴订阅的兜底入口）
```

- **配置中心本身域名被封怎么办：** 三层兜底——① 地址列表里有 3 个不同域名的地址（面板域名、Worker 域名、GitHub Raw / R2 域名），一个被封试下一个；② 本地缓存的最后一份好配置可以撑很久（订阅地址不变的情况下，配置拉不到也不影响已连上的节点）；③ 公告里可以写新地址，用户手动粘贴订阅也能恢复。不要把全部希望押在一个域名上。
- **换域名操作清单（给你用的，不是给用户的）：** ① 新域名解析到面板 / Worker → ② 面板设置里改订阅对外域名 → ③ 远程配置中心改 `panel_domain` / `subscription_url`，`config_version` +1，重新签名 → ④ 用一台已装客户端的手机验证：杀掉重开，订阅自动更新到新地址，旧令牌能用 → ⑤ 发公告。整个过程用户不用重装、不用重新绑定。
- **订阅地址换了，旧订阅令牌怎么办：** 令牌不变（令牌存在面板里，跟订阅路径走，见 §1.3），所以只换地址、不换令牌，用户无感知。如果连令牌也要换（例如令牌泄露），那是另外一件事：面板轮换令牌后，用户须重新绑定，客户端要给出明确的重新绑定入口，不要静默失败。

### 6.5 品牌可替换变量表（摘要，完整表见附录 A）

| 变量 | 存在哪里 | 改完生效方式 |
|---|---|---|
| 应用名、Logo（远程图）、主色、强调色、客服 / 公告链接 | 远程配置 `brand.*` | 重启客户端即生效，不用重新打包 |
| 包内默认 Logo、启动图、包名、应用 ID | 客户端工程 `assets/` / `pubspec.yaml` / 原生工程 | 须重新打包 |

## 7. 界面设计与 Logo

### 7.1 设计原则

- **一屏只做一件事。** 首页 = 开关；节点页 = 选节点；我的页 = 流量、到期、订阅、公告；设置页 = 开关项。不要一屏塞五个功能。
- **默认即正确。** 首次打开默认规则模式、默认自动选节点、默认 DoH，不要让用户先做选择题。
- **状态一眼看得懂。** 已连接 = 绿色大圆 + 速率；未连接 = 灰色；测速中 = 转圈 + ms 数；停用 / 失效 = 红色 + 一句话原因 + 一个处理按钮。
- **不放的东西：** 首页不放日志、不放 DNS 查询、不放规则编辑器、不放多订阅切换、不放协议参数。

### 7.2 页面清单

| 页面 | 放什么 | 不放什么 |
|---|---|---|
| 首页 | 大开关（圆形，直径约 1/3 屏宽）；当前节点名 + 延迟；实时上行 / 下行速率；流量三格（已用 / 总量、剩余、到期日）；模式切换（规则 / 全局 / 直连，三段式）；公告横条（有新公告时才出现） | 日志、DNS、规则列表、订阅 URL 明文 |
| 节点页 | 搜索框（按名字搜）；分组标题（中转 / 直连分组分开）；每行：节点名、延迟、状态角标（明文节点标“明文”）；顶部“一键测速”+“自动选择”两个按钮；当前节点置顶并标“使用中” | 协议参数、UUID、WS 路径（点进详情才看，且 UUID 默认打码） |
| 我的页 | 账号区（订阅名、到期日、剩余流量大字）；订阅更新（上次更新时间 + 刷新按钮）；公告列表；重新绑定 / 退出登录 | 面板管理后台入口、所有用户列表 |
| 设置页（常用） | 开机自启（Windows）/ 后台保活（Android）；订阅自动更新开关；通知开关；语言（先只有简体中文，置灰）；关于（版本号、核心版本、检查更新） | — |
| 设置页（高级，默认折叠） | TUN 开关；DNS 配置查看；分应用代理（Android，P1）；诊断（一键导出诊断包、测速检测）；清除缓存 | 规则编辑器、脚本、插件 |
| 首次启动 | 一页说明（3 行字：这是什么、点一下就能连、流量和到期在哪看）→ 自动拉配置 → 自动拉订阅 → 进首页 | 注册表单、手机号验证、付费墙 |

### 7.3 配色与字体（与 Logo 呼应）

- **Logo 成品 v1**（用户 2026-11-21 23:25 定稿）：深蓝圆角方底（`#16324F` 一带），金色哲人侧脸 + 月桂枝，右侧三道金色信号弧。寓意：哲学（哲人 + 月桂）+ 连接（信号弧）。v2 负空间版（金色信号弧围出的留白哲人侧脸）同目录留作备选。文件为 WebP，实施时须转出 PNG / SVG 各尺寸：启动图标 1024×1024、Android 自适应图标（前景 + 背景分层）、Windows ICO（16 / 32 / 48 / 256）、托盘图标（单色版）。
- **配色：** 主色深海蓝 `#16324F`；强调色琥珀金 `#E8A317`（只用在开关、当前节点、主要按钮，不要大面积铺）；背景浅色 `#F7F8FA` / 深色 `#0F1B2D`（深色模式）；文字主 `#111827`、次 `#6B7280`；成功绿 `#16A34A`、警告橙 `#D97706`、危险红 `#DC2626`。
- **字体：** 中文优先用系统字体（Windows：微软雅黑 / Android：系统默认），不要内置大字体文件；数字（延迟、速率、流量）用等宽数字，避免跳动。
- **圆角与间距：** 卡片圆角 16，按钮圆角 999（胶囊），页面边距 16，列表行高 56。Windows 与 Android 用同一套间距，不要各做一套。

### 7.4 Logo 替换说明

- Logo 文件放在客户端工程 `assets/logo/`，远程配置里的 `brand.logo_url` 可替换首页和“我的”页显示的 Logo（远程图优先，加载失败回退包内 Logo）。
- 应用图标（桌面 / 手机桌面上那个）只能随打包替换，远程配置换不了——改应用图标必须重新打包、重新安装，这一点要在方案里写明，不要给用户错误预期。
- Logo 的 SVG 原稿要在阶段 1 产出（当前只有 WebP 成品图，须在实施时重绘为矢量稿，否则放大 / 换色会糊）。

## 9. 风险与注意事项

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| R1 | 订阅链接被封 | 用户拉不到节点 | 订阅走 Worker 域名（已在用），换域名只改远程配置；备用订阅地址链；订阅更新失败时提示明确原因 |
| R2 | 配置中心域名被封 | 换域名、换订阅的指令下发不出去 | 三地址链 + 本地缓存最后一份好配置 + 手动粘贴订阅兜底（见 §6.4）；不要把配置中心和订阅放在同一个域名上 |
| R3 | 应用商店审核 | 上架被拒 / 下架 | 第一版不走商店，只走官网直发；商店以后单独立项再议 |
| R4 | Windows SmartScreen | 用户装的时候弹“未知发布者” | 先用官网直发 + 绿色 zip；有预算后再买 OV / EV 代码签名证书；安装说明里写清点“仍要运行” |
| R5 | Android 厂商后台杀进程 | 后台断连、消息不提醒 | 前台服务 + 忽略电池优化引导 + 厂商白名单说明（小米 / 华为 / OPPO 各写一句话）；不要承诺“永不断连” |
| R6 | TUN 冲突 | 用户装了别的 VPN / 代理客户端，TUN 抢网卡 | 启动时检测已有 TUN / VPN，冲突时提示“请先退出其他代理客户端”，不要静默抢占 |
| R7 | 面板 API 变化 | 客户端解析失败 | 版本门（`min_panel_version`）+ 订阅解析失败时保留旧节点 + 明确提示升级面板；适配层与界面分离，面板改动只改适配层 |
| R8 | sing-box 大版本升级 | 旧配置格式被移除（例如 1.14 移除 legacy DNS） | 客户端自己生成核心配置，不透传面板的 DNS 段；核心升级单独走验证流程（见 §4.5） |
| R9 | 订阅令牌泄露 | 别人盗用用户流量 | 令牌只存安全存储，不打日志、不进诊断包；面板侧可轮换令牌，客户端给重新绑定入口 |
| R10 | 域名 / 证书过期 | 订阅拉不到、面板打不开 | 远程配置里放 `announcement` 提前通知；证书到期前 7 天面板已有提醒，客户端不再重复提醒 |
| R11 | 用户换手机 / 重装 | 订阅、设置丢失 | 订阅令牌存在面板侧，重新绑定即可恢复；客户端设置可导出一份加密备份文件（P1），不要做账号云同步 |
| R12 | 法律与合规 | 不同地区对代理客户端的规定不同 | 客户端不提供节点、不卖节点，只做用户自有节点的连接工具；官网与应用内不写任何承诺翻墙的文案；具体合规问题以用户当地规定为准，本方案不做法律判断 |

## 10. 未核实项（执行前须再核实，别猜）

1. **面板有没有给客户端用的“用户自查”接口。** 目前只确认了订阅 + `subscription-userinfo` 头；面板代码（`relay-node-kit-160/panel/`）里有没有用订阅令牌查自己流量 / 到期 / 分组的接口，须在阶段 0 通读 `handlers.go` / `subscription.go` 确认。没有就只用订阅 + userinfo 头。
2. **sing-box JSON 的新 DNS 格式字段名。** 面板目前出的是 legacy DNS 格式；客户端自己生成 DNS 配置时，新格式的字段名须对照 sing-box 1.14 官方文档确认。
3. **Xboard / V2board 的具体 API 字段。** 本方案只写了订阅地址形状与 `getSubscribe` / `user/info` 的接口名（来源见 §2），具体请求参数、返回字段、登录方式（邮箱 + 密码 / 令牌）、流量单位、到期时间格式，须在阶段 2 用测试账号实测确认，不要按本文的字段名直接写代码。
4. **Flutter / sing-box 插件最新版本号。** 本方案查到的 Flutter 3.50.1、sing-box 1.14.4、`flutter_sing_box` 3.0.3 都是 2026-11-21 查到的；阶段 0 冻结版本时须重新查最新稳定版，插件的 Windows TUN 支持、URLTest 支持、Clash API 支持须对照最新 README 逐项确认。
5. **Android SDK 在本机能否装下、跑起来。** 本机现无 Flutter / Java / Android SDK，只有 Go 1.22.2，磁盘余 146G；SDK + Flutter 全套约 10G+，阶段 0 安装验证时须实测 `flutter doctor` 全绿、真机安装一次。
6. **Windows 打包走哪条路。** 用户此前定 GitHub 账号无 CI 额度、测试全本地；Windows 包若走 GitHub Actions 须用户另行拍板，否则走用户 Windows 真机打包（装 Flutter + Visual Studio 2022 C++）。
7. **Clash YAML 的 dns 段与策略组在客户端解析时的取舍。** 面板 Clash 订阅含 dns 段、7 个策略组、15 个检测域名；客户端解析 Clash YAML 时是只取节点、还是连同规则一起转，须在阶段 0 定（本方案推荐只取节点、规则由客户端生成）。
8. **Logo 矢量稿。** 现只有 WebP 成品图，须在阶段 1 重绘为 SVG 原稿，否则多尺寸图标会糊；配色以成品图为准（深蓝 `#16324F`、琥珀金 `#E8A317`，以实测取色为准）。
9. **FlClash 的 GitHub 地址。** 搜索结果同时出现 `chen08209/FlClash` 与 `getpool/FlClash` 两个地址，执行时以 GitHub 实际为准，不要直接引用。
10. **Shadowrocket / Streisand 的 Windows / Android 版。** 搜索结果中关于“Shadowrocket 有 Windows / Android 免费版”的说法来自第三方站点，与 App Store 的 iOS 付费版说法不一致；本方案只把它们当 iOS 标杆参考，不把第三方站点的 Windows / Android 版当事实。
