# 客户端账号密码登录接口契约（客户端切片 9）

> 2026-11-23 制定。客户端侧已实现（切片 9），**面板侧接口还不存在**，
> 面板实现时照这份契约做；接口未发布前，客户端的登录页点登录一定报
> “面板连接不上”，这是预期行为，不是客户端 bug。
> 脱敏：本文所有示例一律用 `example.com` / `panel.example.com` /
> `sub_` + 64 位十六进制占位，不含任何真实域名、IP、订阅路径与令牌。

---

## 1. 用途与边界

- 账号密码登录是可选登录（DEV-PLAN §10.2）：免登录（订阅链接 + 令牌）
  是默认，账号登录是补充；两种方式对应**同一个面板用户、同一份流量
  与到期**，不各算一份。
- 客户端用账号登录后，面板返回该账号的订阅链接，客户端按现有订阅流程
  绑定（令牌不变、只换身份），节点、流量、到期都走订阅那条线。
- 本接口只负责“账号 → 会话令牌 + 订阅链接”，不负责拉订阅、查流量、
  下发节点；那些仍走订阅端点（见 `panel-adapter.md`）。

## 2. 端口：9870–9880，默认 9876

- 面板在 **9870–9880（含两端，共 11 个端口）**上监听本接口，与面板管理
  后台的 11111 端口分开；只能开一个端口时开 **9876**。
- 面板侧监听全部 11 个端口还是只监听其中几个，由面板实现决定；
  客户端不假设某个端口一定在听，只按 §5 的顺序逐个试。
- 本接口只走 HTTPS（面板须给这些端口配有效证书；自签证书的面板
  客户端连不上，见 §5）。

## 3. 登录接口

```
POST https://<面板域名>:<端口>/api/v1/client/login
Content-Type: application/json
User-Agent: Zhexuexi/0.1.0
```

### 3.1 请求体

```json
{
  "username": "nianba",
  "password": "********"
}
```

- `username`：面板登录用户名（与管理后台登录用同一套账号体系，
  密码由面板校验）。
- `password`：明文密码，只在本次请求的 TLS 通道内传输；客户端
  **绝不存明文密码**，只存返回的会话令牌。
- 请求体只含这两个字段，不带设备信息、不带位置、不带其它标识。

### 3.2 成功响应（200）

```json
{
  "token": "sess_0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "username": "nianba",
  "subscription_url": "https://example.com/sub-path/sub_0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "expires_at": 1798765432
}
```

| 字段 | 是否必填 | 说明 |
|---|---|---|
| `token` | 必填 | 会话令牌，不透明字符串；客户端存系统密钥库，只在调 `/api/v1/client/*` 时带 `Authorization: Bearer <token>` |
| `username` | 必填 | 回显登录成功的账号名（客户端显示用） |
| `subscription_url` | 选填 | 该账号名下的订阅完整链接（含 `sub_` 令牌）；账号下没有订阅时不给或给空字符串，客户端登录成功但不绑定订阅，用户可再手动绑链接 |
| `expires_at` | 选填 | 会话令牌过期时间（Unix 秒）；不给表示面板侧不限期，客户端不主动按它登出 |

### 3.3 失败响应

| 状态码 | 含义 | 客户端提示 |
|---|---|---|
| 401 | 账号或密码不对（或会话令牌已失效，见 §6） | 账号或密码不对 |
| 404 | 接口不存在（面板版本太旧，没实现本接口） | 面板版本太旧，没有账号登录接口，请先升级面板 |
| 429 | 请求太频繁（响应头带 `Retry-After` 秒数） | 请求太频繁，请稍后再试 |
| 5xx | 面板内部出错 | 面板出错了，请稍后再试 |
| 其它 4xx | 请求非法（缺字段等，开发侧问题） | 登录请求不对，请联系管理员 |

- 失败响应的响应体不作要求，客户端只按状态码映射文案，不读响应体里的
  细节，不把技术细节推给用户。
- **禁止用状态码区分“账号不存在”与“密码不对”**：两种情况都返回 401，
  不给枚举账号的口子。

## 4. 会话令牌

- 格式由面板定（建议 `sess_` + 64 位十六进制，与订阅令牌同等强度，
  随机生成、只存哈希）；客户端把令牌当不透明字符串，不解析、不拼进 URL。
- 令牌只用于 `/api/v1/client/*` 这一组接口；**绝不能用它调管理接口**
  （`/api/v1/subscriptions/*` 等管理员接口仍只认管理员登录会话）。
- 令牌有效期与吊销由面板定；面板侧撤销 / 轮换订阅令牌不影响会话令牌，
  会话令牌被吊销时 §6 的接口返回 401。
- 退出登录是客户端行为：客户端删本地会话令牌即可，不用调面板接口；
  面板不提供“登出”接口（MVP 不做服务端登出）。

## 5. 端口探测规则（客户端实现，面板不用管）

客户端按以下顺序逐个试端口，对每个端口发一次 §3 的登录请求：

1. **上次记住的端口**（如果有）：上次登录成功时服务器实际响应的端口，
   存在客户端本地（shared_preferences，非敏感信息）。
2. **9876**（默认端口；如果第 1 步已经试过 9876 就跳过）。
3. **9870 → 9880 逐个试**，跳过前面已试过的端口。

“通”的定义：收到**任何 HTTP 响应**（无论状态码是 200、401 还是 404）
即为通，客户端记住这个端口，下次优先试它；只有**连接失败 / 超时 /
证书校验失败**才算不通，换下一个端口继续试。

- 单个端口超时 5 秒（连接、发送、接收各 5 秒），11 个端口全试一遍
  最多约 55 秒。
- 11 个端口全不通 → 客户端报“面板连接不上，检查面板域名与网络”，
  不继续重试。
- 收到 HTTP 响应后不再换端口：401 就是账号密码不对，不会因为 401
  再去试下一个端口；404 就是面板版本太旧，也不再试。
- 端口探测只发登录请求，不另发探测请求（如不先 GET / 探活），
  账号密码只发给真正接受连接的端口。

## 6. 令牌撤销与重新登录

- 面板侧撤销 / 轮换订阅令牌后，客户端下次拉订阅时订阅端点按现有口径
  返回 404（令牌查无此人）或 410（订阅已到期）；客户端提示
  “订阅已失效，请重新导入或重新登录”，不静默连不上。
- 会话令牌被面板吊销后，`/api/v1/client/*` 返回 401；客户端收到后
  立即清掉本地会话令牌，回到免登录状态并提示重新登录，不再重试。
- 登录时面板返回的订阅链接拉取失败（404/410）：客户端回滚本次登录
  ——删掉刚存的会话令牌、恢复登录前的订阅绑定，不留半登录态，
  提示“订阅已失效，请重新导入或重新登录”。

## 7. 安全与隐私

- 账号密码只在 HTTPS 请求体内传一次；客户端不存明文密码、不写日志、
  不进诊断包；会话令牌与订阅令牌一样只存系统密钥库。
- 诊断包（设置页“导出诊断”）不含账号、密码、会话令牌、订阅令牌、
  节点地址；只含本机核心与 Clash API 的连通性。
- 找回密码：客户端不做找回页面；密码忘了走面板的找回流程或联系管理员
  （登录页只给一句文字提示）。

## 8. 面板侧实现清单（照着做）

1. 新增监听：9870–9880（只能开一个时开 9876），配有效证书，只走 HTTPS。
2. 新增路由 `POST /api/v1/client/login`，无须事先认证；按 §3.2/§3.3
   返回；401 不区分账号不存在与密码不对；登录失败记数与限流复用面板
   现有的登录防刷逻辑（不要给客户端接口单独留一个不限流的口子）。
3. 登录成功返回该账号的订阅链接（`subscription_url`，完整链接含令牌）；
   账号下没有订阅时不给该字段。
4. 会话令牌的生成、存储（只存哈希）、校验、吊销接口由面板实现；
   令牌只鉴权 `/api/v1/client/*`，不放行管理接口。
